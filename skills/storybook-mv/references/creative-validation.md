# Representative creative validation

Use a small set of actual original probes to test the artistic mechanisms the toolkit claims. Keep their source, recording, rendering, observation and acceptance scopes separate. Do not add new user approval stops or substitute a benchmark for the user's design/sample reviews.

## Validate distinct demands

1. Character interaction: a supported pose, gaze/reaction, prepared reach, contact, ownership transfer and settle, then a motivated transition. Inspect the prop/contact close-up and a playable sequence. A successful stylized handoff is not realistic acting or a universal rig.
2. Original Chinese text: complete readable lines, selected font glyphs, changing hierarchy, intentional reading time and a graphic transition. Use original instrumental audio for redistributable probes and label it instrumental; this is not sung-word alignment.
3. Non-character graphics: deterministic seek, visible development, intentional holds/repeats and an ending or loop. Do not introduce a cast or romance just to reuse a template.

Use `scripts/creative_probe.py <output> --case interaction|type|abstract --canvas-module <selected-module> [--font <local-CJK-font>] --tool-self-test` for the bundled original 12-second mechanisms. All are isolated toolkit self-tests with original code/text and procedural instrumental audio; no user recording, project consent or aesthetic certification is implied. Inspect their actual output and record what failed as well as what worked. Source and machine receipts are reusable; a machine “passed” is not a user taste result.

## Review the accepted design against production

At the existing sample and final reviews compare representative source-bound frames with the accepted design for the same intended moment: subject size, silhouette, palette roles, material/edges, type layout and emotional staging. Include action strips for motion and clips spanning both sides of a cut. Explain deliberate differences. Keep accepted design assets as the baseline instead of quietly lowering quality to make the render cheaper.

Use `media_audit.py compare` for a side-by-side aid. Its grid is not an automatic style or beauty score. Preserve scope/asset rules: code-only design requires code-only production. A differently composed frame may be a deliberate camera change; an agent must inspect context rather than reject numerical pixel difference.

## Exercise destinations honestly

Run the existing contract/media tests and selected CPU runtime, then the actual browser adapter when chosen. The optional `tests/browser_smoke.mjs` exercises local Canvas2D rendering and the review page with a real Chromium process; it does not verify p5/WebGL. Repository CI includes separate Ubuntu browser and Windows native jobs. Report their observed run results rather than turning the presence of a workflow into compatibility evidence. Font availability remains destination-specific.

For a real sung project, use its actual recording and the normal user-approved workflow. Review phrase entrances, held syllables, repeated lines, instrumental sections and the complete cut by listening; preserve canonical line IDs and manual timing evidence. A synthesized instrumental, a periodic pulse, RMS candidates or a caption font test cannot stand in for a finished sung MV. Until an actual complete authorized project is reviewed, keep that capability unverified. Never redistribute its private audio/lyrics/photos through the skill or public test suite.
